# 手机台账专项改进

## 问题与变化

此前仅限制宽表格在容器内部滚动，虽然页面不溢出，手机仍无法方便地同时查看金额、事项摘要、付款状态及操作。四个汇总块和完整筛选表单还把记录推到了页面下方；项目内录入弹窗已有实现但缺少入口。

本次针对项目列表、项目账套和全盘财务明细进行调整：

- 760px 及以下将同一份表格记录展示为纵向卡片，无重复数据或重复表单，保留原有服务端筛选和分页。
- 长名称、摘要和大额数字完整显示，付款与复核状态直接列出，付款说明、来源文件及作废原因可以展开查看。
- 汇总与筛选默认折叠，筛选标题显示已设置的条件数；查询与翻页定位回记录区域。
- 编辑、作废等操作带文字，触摸目标至少 44px。
- 项目账套新增录入入口，自动带入所属项目；明细日期默认当天，金额支持小数键盘。
- 手机弹窗改为单列底部面板，内容单独滚动，操作按钮随表单滚动保持可达；支持 Escape 关闭、键盘焦点约束和关闭后恢复焦点。
- 桌面保留原表格，手机与桌面切换时恢复相应筛选展示方式。

## 验证记录

使用独立临时 SQLite 数据库、虚构长项目名称和 22 条明细，开启 CSRF，未使用生产数据。

- 项目列表、项目账套、全盘明细在 320、375、390、768、1440px 下检查通过；手机表格和单元格无横向滚动或截断，桌面保持表格。
- 首条手机记录进入首屏区域，金额和未支付状态正确展示，编辑按钮高度至少 44px。
- 从项目内第二页设置付款筛选，确认重置页码、保留项目范围、显示活动条件，再清除筛选。
- 展开付款说明；在项目内新增 888.88 元明细并核对数据库所属项目；在 320×568 视口编辑为 999.99 元并标记已支付，再到全盘明细核对状态。
- 弹窗、深色模式和 Escape 关闭检查通过，无 JavaScript 页面异常。
- 台账路由、财务仓库、安全相关测试 52 项通过。

浏览器回归可复现运行（需要 Playwright 与 Chrome）：

```sh
CAM_BROWSER_TESTS=1 .venv/bin/python -m pytest tests/test_ledger_mobile_browser.py -q
```

可用 `CAM_BROWSER_CHANNEL` 选择已安装的浏览器渠道，`CAM_LEDGER_SCREENSHOTS` 指定截图目录。默认测试不会启动浏览器。上述检查为 Chrome 视口模拟，真实手机 Safari / 微信浏览器仍待验收。本次未部署上线。
